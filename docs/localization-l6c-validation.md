## Search implementation and limits

The original table path was `BrowserData::createTreeTOs` →
`NetworkResourceRawTO::matchWithFilter` → byte-oriented
`StringHelper::containsCaseInsensitive`. A second independent caller exists in
`BrowserGalleryWidget::getSortedEntries`. Both GUI callers now use the small
`BrowserMetadataSearch::matches` adapter, reusing the existing `Utf8Search::find`.

The adapter preserves all ten original fields: timestamp, user name, resource
name, download count, width, height, particle count, content size, description
and version. Numeric fields retain `std::to_string` representation. Empty filters
still match every resource. Matching remains substring-based; workspace
visibility, table/gallery sorting, pagination, tree construction and result order
are unchanged. No lowercased strings are stored or serialized.

Case folding covers ASCII A–Z, Russian А–Я and Ё/ё. Е and Ё remain distinct in
both directions. This is deliberately not full Unicode case folding,
normalization, transliteration, stemming, accent folding or locale-dependent
collation. Other valid Unicode code points match exactly. Matching uses decoded
characters and cannot start or end inside a UTF-8 sequence.

Existing strict decoding rejects truncated/stray continuation bytes, invalid lead
bytes, overlong encodings, surrogates and values beyond U+10FFFF. An invalid query
does not match. An invalid field does not match a nonempty query, including an
ASCII substring within that invalid field; other valid fields can still match.
An empty filter still includes resources with malformed metadata. No decoder or
global `StringHelper` implementation was modified. This per-field fail-closed
policy is an explicit limit, not replacement-character matching.

All other `matchWithFilter` consumers were inspected. The MCP resource-search
caller and its existing semantics are preserved. No Network/Base production
implementation, network transfer structure, parser or persisted format changed.

## Identity, state and operation contracts

The new `AccountLocalizationTests` executable renders actual ImGui components
with the real fonts/style at 100%, 150% and 200%. EN → RU → EN checks cover all
six open forms, unchanged modal/window and input IDs, active input/focus without
refocusing on a language change, literal entered values, session state and action
layout bounds. Mouse clicks exercise empty-field disabled actions, password
mismatch, resend using the original email, alternate-email reopening, rejected
email submission and login submission. Existing validation rules are preserved;
the GUI does not add email/password/code validation.

Success and failure handlers exercise creation, activation followed by login,
reset, setting a new password followed by login, and deletion/logout. Exact
credential/code/email arguments and request counts are checked against isolated
responses. Pending asynchronous login is switched between languages without
rescheduling; its raw error is then displayed in an open message whose identity
and arguments survive further switches. Existing L6-B tests similarly cover
pending download/upload/replace/delete/edit/move failures. Existing L6-A overlay
regression retains emit-time notification language and literal payloads.

Owned form and generic-dialog prose resolves at display time. Already emitted
overlays retain event-time language. External diagnostics remain untranslated.
The original request order, response handling (including existing result
combination), remember behavior, session transitions and clearing rules remain
unchanged. Source comparisons check network calls, arguments, branches, disabled
conditions, settings keys and request construction against the stated base.

The account executable provides every public `NetworkService` method through a
test-only link-time implementation; unexpected operations fail the test and no
HTTP client is used. Persister, rendering and GPU-name dependencies use isolated
facade stubs. The test process uses `SettingsTestScope` to redirect settings away
from the real user profile. No real login, registration, password change,
account deletion or user-resource mutation was performed.

## Limits and preservation

This is automated real ImGui/font/state testing and source-contract review,
not manual Vulkan desktop or screenshot acceptance. Hovered tooltip appearance,
final desktop composition, unusual saved narrow-window sizes and real server
account workflows remain unverified. A live authenticated session, delivery of
email codes, real concurrent server responses and server-side account semantics
were deliberately not exercised. Synchronous NetworkService operations cannot
switch language midway through their blocking call; asynchronous persister
callbacks were tested with queued isolated responses.

No additional manual-acceptance build was prepared. L6-D is untouched and the
entire L6 stage is not declared closed. `main` remains at the requested baseline.
`AGENTS.md` retains skip-worktree and SHA-256
`090C381A6F2B1F62597108DE236E53131559FFEF796146011A5796DBB7EF3368`.
User worlds, genomes, autosaves, settings and dependencies are preserved.
Pinned vcpkg is unchanged. No CodeQL, submodule update or IDE-tree build ran.
